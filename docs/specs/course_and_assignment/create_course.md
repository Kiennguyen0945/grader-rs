
## Goal

Allow user to create a course

## Actors

Actor: Lecturer

## Entities

- `id`
- `code`
- `course_name`
- `description`

## Features

- create course
- retrieve a course
- get a list of course

## Rules

- `id` is generated by the database.
- `code` is required and unique.
- `course_name` is required.
- `description` is optional.

## Basic flow


### Create Course
1. The user sends a request to course API
2. API validates the incoming data
3. API checks course uniqueness
4. API creates a new course
5. API returns the new course

### Get Courses

1. The client sends a GET request to `/api/courses`.
2. The API retrieves all courses.
3. The API returns the courses.

### Get Course

1. The client sends a GET request to `/api/courses/{courseId}`.
2. The API searches for the course.
3. The API returns the course.


## Failure flows

- If code is missing, return a validation error.
- If code already exists, return a conflict error.
- If the request body is malformed, return a bad-request error.
- If saving fails, return a server error.
- If the course does not exist, return a not-found error.

## Endpoints

POST   /api/courses
GET    /api/courses
GET    /api/courses/{id}
PATCH  /api/courses/{id}
DELETE /api/courses/{id}
GET    /api/courses?code=CS505

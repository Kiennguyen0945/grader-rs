
## Goal

Allow a lecturer to create and manage test cases for an assignment.

## Actor

Lecturer

## Entity

- `id`
- `assignment_id`
- `name`
- `input`
- `expected_output`
- `is_public`
- `display_order`

## Features

- Create a test case
- List test cases for an assignment
- View one test case
- Update a test case
- Delete a test case

## Rules

- `id` is generated by the database.
- `assignment_id` is required and must refer to an existing assignment.
- `name` is optional.
- If provided, `name` must be unique within the assignment.
- `input` may be empty because some programs require no input.
- `expected_output` is required.
- `is_public` defaults to `false`.
- `display_order` is assigned by the application.
- `display_order` must be unique within the assignment.
- Test cases cannot be changed after the assignment has received submissions.
- Only the lecturer who manages the assignment may manage its test cases.

## Main flows

### Create Test Case

1. The lecturer selects an assignment.
2. The lecturer enters the test name, input, and expected output.
3. The lecturer chooses whether the test is public or hidden.
4. The system verifies that the assignment exists.
5. The system validates the test data.
6. The system assigns the next display order.
7. The system stores the test case.
8. The system returns the created test case.

### List Test Cases

1. The lecturer requests the test cases for an assignment.
2. The system verifies that the assignment exists.
3. The system retrieves the test cases ordered by `display_order`.
4. The system returns the test cases.

### Update Test Case

1. The lecturer requests an update.
2. The system verifies that the test case exists.
3. The system validates the supplied fields.
4. The system updates the test case.
5. The system returns the updated test case.

### Delete Test Case

1. The lecturer requests deletion.
2. The system verifies that the test case exists.
3. The system verifies that the assignment has no submissions.
4. The system deletes the test case.
5. The system returns `204 No Content`.

## Failure flows

- If the assignment does not exist, return `404 Not Found`.
- If the test case does not exist, return `404 Not Found`.
- If `expected_output` is missing, return a validation error.
- If the test name is duplicated within the assignment, return `409 Conflict`.
- If the assignment already has submissions, reject modification or deletion.
- If the lecturer does not manage the assignment, return `403 Forbidden`.
- If the request body is malformed, return `400 Bad Request`.

## Endpoints

POST   `/api/assignments/{assignmentId}/tests`

GET    `/api/assignments/{assignmentId}/tests`

GET    `/api/tests/{testId}`

PATCH  `/api/tests/{testId}`

DELETE `/api/tests/{testId}`

## Request examples

Request
{
  "name" : "Print",
  "input" : "",
  "expected_output" : "Hello World",
  "is_public" : true,
}
Response
{
  "id": 1,
  "name": "Print",
  "input": "",
  "expected_output": "Hello World",
  "is_public" : true,
  "display_order" : 1
}

Your draft has the right direction, but several details need correction:

- A submission should start as `QUEUED`, not `DRAFT`.
- The client should not send `status` or `grade`; the server controls them.
- A submission should belong to both an assignment and a student.
- Submissions should normally be immutable, so postpone `PATCH` and `DELETE`.
- `grade` should be `null` until grading finishes.
- `GET /assignments/{assignmentId}/submissions` should be restricted to authorized users, such as lecturers.

Here is a polished first MVP draft:

```markdown
## Goal

Allow a student to submit source code for an assignment and view the submission status.

## Actors

- Student: creates and views their own submissions.
- Lecturer: views submissions for assignments they manage.

## Entity

- `id`
- `assignment_id`
- `student_id`
- `source_code`
- `status`
- `grade`
- `attempt_number`

## Features

- Create a submission
- View a submission
- View submissions for an assignment
- Track submission status

## Rules

- `id` is generated by the database.
- `assignment_id` is required.
- `student_id` is required.
- `source_code` is required.
- `status` is assigned by the system.
- A new submission starts with status `QUEUED`.
- `grade` is initially `null`.
- The grade is assigned by the grading process.
- A submission cannot be modified after it is created.
- A student may submit only while the assignment is open.
- A student cannot exceed the assignment's submission limit.
- A student can view only their own submissions.
- A lecturer can view submissions for assignments they manage.

## Submission statuses

```text
QUEUED
RUNNING
ACCEPTED
WRONG_ANSWER
COMPILE_ERROR
TIME_LIMIT_EXCEEDED
MEMORY_LIMIT_EXCEEDED
RUNTIME_ERROR
SYSTEM_ERROR
```

## Basic flow: Create Submission

1. The student selects an assignment.
2. The student enters source code.
3. The student sends a `POST` request.
4. The API verifies that the assignment exists.
5. The API verifies that the assignment accepts submissions.
6. The API validates the source code.
7. The API determines the student's attempt number.
8. The API creates the submission with status `QUEUED`.
9. The API stores the submission.
10. The API returns the created submission.

The grading process is not performed during this request. It will be added later.

## Failure flows

- If the assignment does not exist, return `404 Not Found`.
- If the source code is missing or empty, return a validation error.
- If the assignment is closed, return `409 Conflict`.
- If the submission limit has been reached, return `409 Conflict`.
- If the student is not allowed to submit to the assignment, return `403 Forbidden`.
- If the request body is malformed, return `400 Bad Request`.
- If saving fails, return `500 Internal Server Error`.
